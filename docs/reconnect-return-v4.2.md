# Dice Match v4.2 — 기존 플레이어 재접속

## 원인
기존 `/join`은 `guestToken`이 이미 존재하면 언제나 HTTP 409를 반환합니다. 따라서 경기 중 튕긴 플레이어가 6자리 초대 코드만 입력해도 기존 자리를 되찾을 수 없습니다. 또한 시크릿 창을 모두 종료하면 해당 창의 `sessionStorage` 인증 토큰은 사라질 수 있습니다.

## 처리
- 게임방 생성 및 참가 시 플레이어마다 16자리 **비공개 복귀 코드**를 별도로 발급합니다.
- 대기실과 경기 화면에서 개인 복귀 코드를 확인·복사할 수 있습니다.
- 시크릿 창을 완전히 닫기 전 개인 복귀 코드를 별도로 기록해야 합니다. 이 코드는 상대 플레이어와 공유하면 안 됩니다.
- `online.html` → 시작하기 → `진행 중인 경기로 돌아가기`에서 **6자리 초대 코드 + 개인 복귀 코드**로 기존 자리를 인증합니다.
- 서버 `POST /rooms/{code}/recover`: 최초 두 플레이어 경기 화면 연결 완료, 진행 중인 경기, 해당 플레이어가 끊긴 상태, 60초 제한 전이라는 조건을 모두 확인한 뒤에만 원래 seat/token을 돌려줍니다.
- 6자리 초대 코드만으로는 재접속을 허용하지 않습니다. 제3자의 자리 탈취를 방지합니다.
- 종료 경기, 잘못된 코드, 60초 초과, 아직 접속 중인 플레이어는 복귀를 거절합니다.
- 복귀 완료 후 기존 상태와 revision을 유지하고, 양쪽 WebSocket이 연결되면 일시 정지가 해제됩니다.

## 변경 파일
`worker/index.mjs`, `online.html`, `online-game.html`, `js/online-lobby.js`, `js/online-game.js`, `css/online.css`, `tests/online-recovery.test.js`, `docs/reconnect-return-v4.2.md`.

`js/online-config.js`는 포함하지 않았습니다. AI/로컬 대전과 기존 경기 규칙도 변경하지 않았습니다.

## 배포/수동 테스트
1. 기존 프로젝트 백업. ZIP 파일의 변경 파일만 덮어쓰기.
2. `cd C:\workspace\dice-match\worker`; `$env:CLOUDFLARE_ACCOUNT_ID = "<your existing account id>"`; `npx wrangler deploy`.
3. **새 방**을 생성하고 각 플레이어 자신의 비공개 복귀 코드를 따로 복사.
4. 양쪽 준비 후 경기 진입, 2~3회 주사위 배치.
5. 시크릿 창 완전 종료, 일반 Chrome에서 60초 일시 정지 확인.
6. 새 시크릿 창 `online.html` → 시작하기 → 기존 경기로 돌아가기 → 방 코드 + **시크릿 플레이어의 개인 복귀 코드** 입력.
7. 원래 플레이어 2 자리와 기존 경기판으로 돌아오고 일시 정지가 해제되는지 확인.
8. 잘못된 코드, 60초 초과 시 복귀 실패도 확인.

**한계:** 과거 버전에서 생성된 방에는 개인 복귀 코드가 없으므로 새 방에서 테스트해야 합니다. 새 시크릿 창으로 돌아오더라도 비공개 복귀 코드를 따로 저장하지 않았다면 복원할 수 없습니다. 코드를 입력하면 기존 seat에 대해 새 세션 토큰을 받는 방식입니다. 복귀 코드는 해당 게임방에 유효하며, 외부 공개하지 마세요.
