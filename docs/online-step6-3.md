# STEP 6-3 — 온라인 대전 게임 동기화 (로컬 코드 검증 완료)

## 구현 범위

- 기존 `js/engine/game.js` 규칙을 복사한 `worker/engine.mjs`를 **Cloudflare Durable Object 서버**에서 사용합니다. 두 엔진의 로직을 함께 수정해야 합니다.
- 2명이 방에 입장하면 서버가 무작위 선공과 시작 실드 주사위를 생성합니다.
- 서버가 각 행동에서 플레이어/턴/게임 단계/배치 가능 위치/1회 리롤을 검증합니다.
- 서버에서만 주사위 난수를 생성하고 공격·보상 실드·최종 승패를 계산합니다. 클라이언트의 점수나 주사위판은 수용하지 않습니다.
- 모든 승인된 행동은 서버 저장소에 보관하고, WebSocket으로 양쪽 클라이언트에 전달합니다.
- 브라우저 탭 새로고침 시 `sessionStorage`의 기존 입장 토큰으로 경기 상태를 다시 요청합니다.
- `online-game.html`에서 양쪽이 같은 보드를 보되 **본인 차례에만** 배치·리롤 조작이 활성화됩니다.
- 경기 종료 시 기존처럼 1초 후 보드 오버레이를 표시합니다. 경기 재시작은 새 방을 만드는 것으로 대체합니다.

## 실행 절차 (Windows 11)

프로젝트 루트에서 첫 번째 터미널:

```powershell
cd worker
npm install
npx wrangler dev --port 8787
```

`js/online-config.js`에서:

```js
window.DICE_MATCH_SERVER_URL = 'http://127.0.0.1:8787';
```

프로젝트 루트의 두 번째 터미널:

```powershell
py -m http.server 5500
```

서로 다른 브라우저 프로필/일반+시크릿 창에서 `http://127.0.0.1:5500/online.html`에 접속합니다.
방장을 생성하고 친구 코드로 참여한 뒤, 양쪽에서 **온라인 대전 시작**을 누릅니다.

`npm test`는 Node.js 단위 테스트를 실행합니다.

## 미검증과 제약

- **실제 Cloudflare 배포와 두 PC 간 인터넷 대전, 브라우저 시각 효과, 네트워크 지연은 아직 검증하지 못했습니다.**
- 연결이 끊어지면 기존 대국 상태는 유지되지만 자동 재연결은 하지 않습니다. 새로고침 후 복구를 시도해야 합니다.
- 방은 생성 후 최대 6시간 유효합니다. 만료된 방은 삭제되지 않습니다.
- 대기실의 방 나가기/다시 입장은 현재 참가자 슬롯을 비우지 않습니다.
- 방장의 강제 종료, 새로운 경기 재시작 투표, 관전자, 채팅, 랭킹/전적 저장은 범위 밖입니다.
- 게임이 끝난 후 결과는 중앙 게임판 오버레이로 표시됩니다. `대기실로` 링크는 현재 방을 유지할 수 있으므로 새 게임에는 새 방이 필요합니다.
- 두 플레이어가 동시에 행동을 보낼 때 오래된 `revision`은 409 오류로 거부됩니다.
- **비용**: Cloudflare Workers 무료 한도 내 월 0원 목표입니다. 정책 및 사용량은 별도 확인이 필요하며 유료로 자동 전환하는 작업은 수행하지 않았습니다.
- `js/online-config.js`는 기본적으로 서버 주소가 비어 있습니다. 실제 서버에 배포하거나 직접 로컬 서버를 실행해야 합니다.
